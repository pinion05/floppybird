## ⚠️ IMPORTANT — 잠재/실기 관련

### 임베디드 C (리뷰어 A)

**A1. 클럭 트리가 모든 STM32F0 파트에서 스펙 아웃**
`firmware/stm32f0/main.c:247-249, 260`
`RCC_PLLSOURCE_HSI / RCC_PLL_MUL12` → 8MHz HSI × 12 = **96MHz SYSCLK**, `FLASH_LATENCY_1` (1 wait state). STM32F0 플래시는 48MHz 이상에서 2 WS 필요 (일부 파트는 48MHz 자체가 최대). 실리콘에서 폴트 또는 플래시 읽기 깨짐. 모든 empirical `vfd_delay_*` 루프 카운트 (튜닝된 클럭 기반)도 무효. README도 "실기 전 남은 6단계"에서 인정. 정확한 MCU 식별 후 재측정 필수.

**A2. UART/USB 수신 경로 미구현 — 호스트 링크가 현재 데드코드**
`firmware/stm32f0/stm32f0xx_it.c`, `main.c`
`stm32f0xx_it.c`는 `NMI/HardFault/SysTick/TIM14`만 배선. `USARTx_IRQHandler`/`USB_IRQHandler` 없음, `HAL_UART_Receive_IT`/RX 콜백 없음, `VFD_HostProcessByte()`를 호출하는 곳 0곳. 실기에 올리면 부트 데모(`render_supplied_demo()`, `main.c:194`)만 표시되고 호스트 프레임 절대 못 받음. 함수 자체는 정확하지만 호출자 없음. README 단계 6이 이거 지칭.

**A3. 트윈은 인터럽트 마스킹 검증 못 함 (실기에선 정상)**
`main.c:105-115`의 `vfd_scan_event_take()` save/restore PRIMASK 패턴은 실기에선 정확. 단 `tests/target_stubs/stm32f0xx_hal.h:98-101`이 `__get_PRIMASK()`를 항상 0 반환 → strict `-Werror` 보드 빌드가 restore 로직 증명 못 함. 실기 정상, 트윈 신뢰 금지.

**A4. `vfd_scan_due` 단일 coalescing 플래그**
`main.c:21`, `stm32f0xx_it.c:72`. 한 phase emit이 TIM14 주기(96MHz 가정 156.25µs) 넘으면 tick 드롭. 결과는 corruption 아닌 **refresh rate 저하/깜빡임**. 상태기는 phase당 정확히 1 phase 전진, swap은 phase==1 게이트. 설계 선택이지만 per-phase 작업 ~150µs 미만 유지 전제. `main.c`에 코멘트 추가 권장.

**A5. `font8x16[4][16]` 초기화 14바이트만 제공**
`firmware/stm32f0/font.c:16-21`. 각 행 14개 값, 배열은 16. C가 허용해서 `[14][15]`는 0. `PutFont8x16ToBuff`가 `column*2+1` (max index 15) 읽음 → 0 패딩 읽음. 지금은 0이라 정상 렌더, 견고성 함정. `[4][14]`로 축소 또는 16으로 명시 패딩 권장. (다른 폰트 `font5x7[4][5]`, `font7x8[4][7]`, `font15x16[5][30]`은 전부 사이즈 일치.)

### Python 호스트 (리뷰어 B)

**B1. Serial bridge가 ACK desync에 치명 반응**
`src/mn12832l/serial_bridge.py:35-62`
`run_bridge`는 각 write 후 정확히 `ACK_PACKET_BYTES`(9) 읽음. MCU 스트림이 한 번이라도 밀리면 (스트레이 바이트, 노이즈, partial ACK) `decode_ack`가 `BridgeError` raise → bridge exit 1. 다음 대기 프레임 유실, 외부 재시작까지 transport 사망. **펌웨어는 magic 바이트로 resync하지만 Python bridge는 안 함.** "영구 proxy" 설계에 가용성 갭. 수정: decode 실패 시 `VF` magic 재스캔 후 복구 시도, 또는 한 corrupt ACK가 bridge 종료시킨다는 점 문서화.

**B2. `SubprocessTransport` 쓰기 타임아웃 없음**
`src/mn12832l/transport.py:139-146`
`_write_all`이 blocking `os.write`. 자식이 stdin drain 멈추면 (bridge wedge) `self._lock` 잡은 채 무한 블록. 읽기는 deadline 있음(`_read_exact`), 쓰기는 없음. 수정: 같은 deadline으로 write fd `select`, 또는 non-blocking.

**B3. CRC_ERROR 재전송이 동일 바이트**
`src/mn12832l/display.py:55, 129-147`
`_RETRYABLE = frozenset((BUSY, CRC_ERROR))`. 패킷은 retry 루프 전 한 번 빌드 → 매 retry 동일 바이트. 일시적 회선 노이즈면 정상. 호스트 버퍼 문제면 재전송 무의미. 디폴트 동작 방어 가능하지만 한 줄 코멘트 + 운영자에게 `CRC_ERROR` retry 폭풍 = 링크 문제 알림 필요. ACK 회신 경로의 `ProtocolError`는 retry 불가 → 비대칭 견고성.

**B4. 트윈 swap 타이밍이 펌웨어와 다름**
`tools/vfd_system_twin.c:33-37`
시스템 트윈은 OK ACK 후 **즉시** `vfd_host_link_swap_if_pending` 호출 후 front buffer pin trace 출력. 실기는 phase-43→1 경계에서만 swap (`main.c:223-224`). → 트윈은 "이 프레임이 정확히 스캔됨"은 검증하지만 **더블버퍼링/swap-phase 타이밍 및 `RECEIVE_MODE_COMPARE_PENDING`/`BUSY`/`receive_matches_existing` short-circuit 경로는 검증 안 함**. 내용 충실도 증명됨, 시간적/swap-프로토콜 충실도는 아님. 알려진 경계, 버그 아님. README의 "round-trip" 프레이밍이 실제보다 강함. 문서에 명시 권장.

**B5. 헤드라인 라운드트립 테스트, C 트윈 빌드 없으면 조용히 skip**
`tests/python/test_twin.py:87-91, 167-171`
`PinTwinIntegrationTests`, `SystemTwinEndToEndTests`가 `MN12832L_PIN_TWIN`/`MN12832L_SYSTEM_TWIN` 미설정 시 `skipTest`. 이 체크아웃 `build/`엔 `test_vfd_font`, `test_vfd_host_link`, `test_vfd_scan`, `vfd_host_link_peer` 있지만 **`vfd_pin_twin`, `vfd_system_twin` 없음**. bare `python -m unittest discover`는 순수 Python `DigitalTwinUnitTests`만 돌리고 실제 C 라운드트립 증명 skip. `make test-python`은 빌드 먼저 (`Makefile:100-106`) → CI는 OK. 직접 돌리는 사람 거짓 커버리지. 제안: skip 시 경고 출력, 또는 `make twin`을 문서화된 디폴트 진입점으로.

### UI/메뉴 (리뷰어 C)

**C2. 폰트 로드 실패 폴백이 런타임에 감지 불가**
`src/mn12832l/menu/render.py:32-41`
`except OSError: return ImageFont.load_default()`. Pillow 12 (`pillow 12.3.0` 설치됨)에서 `load_default()`가 이제 `FreeTypeFont` 반환 → silent 폴백이 성공과 타입으로 구분 불가, **로깅 없음**. 메뉴가 조용히 잘못된 폰트로 렌더. CI는 glyph metric 비교 (`test_font_loads_galmuri_not_default`)로 잡지만 친구 기기 설치 깨지면 조용히 틀림. 로딩 메커니즘 자체 (`resources.files().joinpath().read_bytes()` → `BytesIO`)는 **정확하고 견고** (Strengths 참조). 수정: except에 `logging.getLogger(__name__).warning(...)`, 또는 dev 모드 첫 사용 시 raise.

**C3. Presenter가 dedup 프레임에서 stale twin stats 보고**
`src/mn12832l/menu/presenter.py:46-81`
`VfdDisplay.present()`가 동일 프레임 dedup (`PresentResult(sent=False)`) 시 transport 호출 안 함 → `self._transport.last_result`는 **이전 상이 프레임 결과** 보존. presenter가 무조건 `_last_verified = twin.reconstructed_frame` 설정, `twin_passed=True`로 stale stats 반환. 화면 픽셀은 정확 (검증된 프레임이 실제 표시), Tk status bar의 `PHASE/CLOCK/LAT`은 마지막으로 달랐던 프레임 기준. 정적 메뉴에선 안 보임, 부트 스캔바 중엔 어차피 매 tick 변경 → self-heal. 화장적. 수정: `present()`에서 `sent` 캡처, `sent is True`일 때만 `_last_verified`/`_last_stats` refresh.

### 벤더 변환 (리뷰어 D)

**D1. Vendored CI/도구 설정이 floppybird repo 루트에서 inert**
드라이버 설정이 이제 `mn12832l-stm32-driver/.coderabbit.yaml`, `.semgrep.yaml`, `.qlty/qlty.toml`, `.qlty/.gitignore`에 있음. floppybird **루트**엔 `.coderabbit.yaml`/`.semgrep.yaml`/`.qlty`/`.github` 없음. CodeRabbit과 Qlty는 **repo 루트**에서 config 발견 → 벤더 서브디렉토리에 있으면 적용 안 됨. semgrep 규칙은 `paths.include: /firmware/stm32f0/*.c` (anchored, sempeg CWD 기준) → 벤더 디렉토리 안에서 실행해야만 매칭. 이 검사들을 vendored 코드에 계속 돌릴 의도면 루트 레벨 config (또는 vendor 디렉토리 cd하는 워크플로) 필요. 변환 *정확성* 결함은 아님 (파일은 충실히 벤더됨) — "여전히 동작하나" 질문.

**D2. 버전 드리프트는 의도적이나 기록 가치**
서브모듈 gitlink는 `2d073e6` 고정, 벤더 트리는 `3d35cc7` (10커밋 신규: Galmuri7 폰트 배포 수정, BOOT 워드마크, 크로스랭귀지 테스트 추가). `2d073e6`은 `3d35cc7`의 strict ancestor (`git merge-base --is-ancestor` 검증). 커밋 메시지와 일치. 데이터 손실 없음. 단 gitlink와 벤더 스냅샷이 다른 리비전이라는 점 — 구 gitlink와 새 파일 diff하면 변환 산물이 아닌 진짜 upstream 커밋의 변경사항이 보임.

## 💪 진짜 잘된 것 (팀 공통)

### C 펌웨어 (리뷰어 A)
- **스캔 드라이버 수학 증명됨.** `vfd_scan.c`에 `_Static_assert` 4개가 기하학 고정: `PAGE_COUNT*8==HEIGHT`, `PIXEL_BITS==HEIGHT*6`, `PIXEL+GRID==FRAME_BYTES*8`, `(PHASES-1)*3+2==WIDTH`. lane 매핑 (odd/even phase 인터리빙) `test_vfd_scan.c`에서 property-test. 수동 재유도 전부 정확.
- **더블버퍼 swap이 스캔에 원자적.** `vfd_host_link_swap_if_pending`은 main 루프 phase==1 (43→1 경계)에서만 호출, ISR 아님. back buffer는 `feed()` 중 쓰고 `front_index ^= 1u`만 가시성 전환 → 스캔이 half-written 프레임 안 읽음. CRC 실패/헤더 무효 패킷은 `pending` 안 세팅 → corrupt 프레임 절대 가시화 안 됨 (`test_bad_crc_never_becomes_visible` 증명).
- **Safe shutdown이 진짜이고 중복적.** `VFD_SafeShutdown`이 blank 먼저, 그리고 HV drop, 그리고 EF — ghost emission 피하는 올바른 순서. `HardFault_Handler`, `NMI_Handler`, `_Error_Handler`에서 호출 + `MX_GPIO_Init`/`main()`에서 예방적. fail-safe 핀 레벨이 핀 output 전환 전 `HAL_GPIO_WritePin`으로 preload → glitch window 없음. 디지털 트윈 `decode_pin_trace`가 END에서 `BLANK=1, HV=0, EF=0` 강제.
- **호스트 링크 프로토콜 수신기 견고.** magic 바이트 프레이밍 + 단일 바이트 resync (스트레이 `MAGIC_0`가 noise 중 깨끗이 재시작), 가시성 전 CRC 전체 검증, 중복 시퀀스 idempotent ACK, frame pending 시 `BUSY` backpressure. little-endian 필드가 Python `protocol.py`와 정확 일치 (전부 교차 검증: magic `0x56,0x46`="VF", version 1, 8바이트 헤더, 2바이트 CRC, 512 페이로드, 522 패킷, 9바이트 ACK).
- **크로스랭귀지 계약 진짜 시행.** `test_cross_lang_constants.py`가 C 헤더를 (빌드 산물 아닌) 파싱해 Python 모듈과 비교 — 프로토콜 상수, 기하 (128/32/4/43/192/48), 9개 핀 이벤트 코드 (1-9), `VFDTPIN1` 트레이스 헤더 전부.
- **Delay 루프 비최적화 가능.** `vfd_delay.c`가 `volatile` 루프 카운터 + `__asm__ volatile("nop" ::: "memory")` 바디. `check_delay_codegen.py`가 Cortex-M0 `-O2` 출력 disassemble해 각 함수에 `nop`과 루프 back-edge 요구 — 타이밍 elide 방지 가드.
- **도구가 스캔 코어와 보드 글루를 깔끔히 분리.** `vfd_pin_twin`/`vfd_system_twin`이 (카피 아닌) production `vfd_scan.c`/`vfd_host_link.c` 링크, GPIO/UART 경계만 stub. Makefile이 동일 `.c`를 테스트/트윈/타겟용으로 빌드. "시뮬레이션 전용" 스캔 코드 포크 없음.

### Python 호스트 (리뷰어 B)
- **트윈 검증이 진짜.** `twin.py:309` byte-exact 비교 (`!=`), tolerance 없음. mismatch 시 `DigitalTwinError` raise (`twin.py:321-324`), `DigitalTwinResult.matches_source`가 source frame 없이 True 반환 불가 (`twin.py:117-124`), `render_tui`가 False일 때 `UNVERIFIED` 출력 (PASS 아님). production에 stub/fallback simulation 경로 없음.
- **`vfd_system_twin.c`가 진짜 펌웨어 소스에서 빌드.** `Makefile:75-81`이 `firmware/stm32f0/vfd_host_link.c` + `vfd_scan.c` 링크. `process_packet`이 `vfd_host_link_feed`를 바이트 단위로 구동 — 하드웨어의 `VFD_HostProcessByte`와 동일. `_reconstruct_frame`이 production 스캔 패커의 충실한 역 (lane swap, grid selector, phase-43 경계 전부 실행으로 검증).
- **CRC 정규 벡터 테스트.** `test_protocol.py:19-20`이 `crc16_ccitt(b"123456789") == 0x29B1` (표준 CRC-16/CCITT-FALSE 체크밸류) 단언 → Python↔C 자기일치 아닌 외부 기준 교차검증. C도 일치 (init `0xffff`, poly `0x1021`).
- **크로스랭귀지 상수 테스트가 헤더를 파싱.** hardcode 아님 → 한쪽 상수 변경 시 테스트 깨짐. trace 헤더 추출의 이전 false-pass 버그 (`test_cross_lang_constants.py:238-260`)까지 문서화하고 C 헤더 못 찾으면 명시적 fail. 정직하고 견고.
- **엔디안 일관적.** sequence/length/CRC 전부 Python (`protocol.py:80-85`)과 C (`vfd_host_link.c:78-84, 125-131`)에서 little-endian. `_Static_assert`가 패킷 사이즈 고정.
- **치수가 모든 경계에서 강제.** `encode_frame`, `VfdDisplay.present`, `run_digital_twin`, `MvlsbRenderer.load_image`, `decode_pin_trace` 전부 512바이트/128×32 계약 체크. silent truncation 경로 없음.
- **리소스 정리 일관적.** `SubprocessTransport.close`가 stdin 닫고 wait, terminate→kill 에스컬레이션. `VfdDisplay`/`serial.Serial` context manager. 예외 경로에서 zombie subprocess/leaked serial 없음.
- **트윈이 fail-safe shutdown 핀 상태 검증.** `decode_pin_trace`가 END에서 `BLANK==1, HV==0, EF==0` 강제 → `main.c:VFD_SafeShutdown` 안전 보증 직접 exercise.

### UI/메뉴 (리뷰어 C)
- **폰트 로딩이 3번의 수정 끝에 진짜 견고.** 실제 wheel 빌드해 `mn12832l/assets/Galmuri7.ttf` (3,702,440 B)와 `loading_wordmark.txt` (294 B) 포함 확인 — `package-data = ["assets/*.txt", "assets/*.ttf"]` 작동. `read_bytes()` + `BytesIO` (`render.py:32-41`)가 이전 3 실패 모드 (zipapp `joinpath('..')` 비정규화, `str(Traversable)` 실제 경로 아님, `as_file()` temp 파일 수명 vs `@lru_cache`)를 회피. `@lru_cache(maxsize=4)`는 `BytesIO`가 `FreeTypeFont` 생성 시 정확히 한 번 소비되고 폰트 객체가 캐시되므로 안전. 전용 회귀 테스트 3개가 Pillow-12 `load_default`도 `FreeTypeFont` 반환하는 점 인지해 타입명 아닌 glyph metric 비교.

## 부록: 리뷰어별 상세 Minor (참고용)

### 리뷰어 A (임베디드 C) Minor
1. `_Static_assert(sizeof(VfdHostLink) <= 1080u)` magic number — `#define VFD_HOST_LINK_RAM_BUDGET 1080u` + 코멘트 권장
2. `stm32f0xx_hal_msp.c` NVIC 우선순위 전부 `0,0` — 단일 IRQ 설계에선 안전, M0에선 두번째 인자 무시라 약간 misleadding
3. `HAL_TIM_Base_MspDeInit` 미호출 — dead code, 무해
4. `VFD_SafeShutdown` guard + `MX_GPIO_Init` 시퀀스 — belt-and-suspenders, 정상
5. `vfd_pin_trace.c` `twin_emit` value 처리 — 일관적, 형식 compact (2바이트/이벤트)
6. `vfd_system_twin.c` `read_packet` partial frame 시 exit 2 — pipe transport에선 적절

### 리뷰어 B (Python 호스트) Minor
6. POSIX-only transport, 미문서화 — Windows에서 select socket 전용이라 hang
7. `pid` property lock 없이 process state 읽음 — TOCTOU vs `close()`, 저임팩트
8. `run_digital_twin`이 wire-protocol 경로 검증 안 함 — `vfd_pin_twin`이 raw 512바이트 직접 읽어 `vfd_host_link_feed` bypass
9. `decode_ack`가 CRC 전 구조 필드 검사 — fixed 9바이트라 exploit 불가, 관례상 CRC-first
10. `serial_bridge.run_bridge`가 호스트 검증 없이 프레임 패킷 forward — dumb proxy 설계, MCU 검증
11. 동일 프레임 skip 시 `last_result` refresh 안 됨 — 올바르나 코멘트 필요

### 리뷰어 C (UI/메뉴) Minor
